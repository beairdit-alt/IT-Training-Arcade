1. Linux Architecture

Linux architecture can be visualized as a stack of layers. Each layer does a different job, but they work together whenever an administrator types a command.

User / Admin
Decides what task to perform
↓
Applications & Utilities
ls cp grep systemctl
↓
Shell
Bash interprets commands and launches programs
↓
Daemons
sshd, cron, docker
Package Manager
apt, dnf
↓
Kernel
CPU, memory, drivers, storage, network stack
↓
Hardware
Disk, NIC, RAM, CPU

Key Idea

The shell is not the operating system itself. It is the interface that lets you talk to Linux. The kernel is the core part that actually manages hardware and system resources.

Example thought process
You type: ls /etc
Bash reads the command
Linux launches the ls utility
The kernel helps it access the disk
The terminal shows the result
Which Linux component directly manages CPU, memory, and hardware drivers?
Correct answer: Kernel. The Linux kernel is the core that manages system resources such as the CPU, memory, hardware drivers, storage access, and networking.

🔎 Deeper explanation: How a command travels through Linux

1. Terminal

The terminal emulator displays a prompt, accepts typed input, and shows output. It is a window into a command-line session, not the operating system itself.

2. Shell

Bash interprets command syntax, expands variables and wildcards, handles redirects and pipes, and starts requested programs. Built-ins such as cd run inside the shell.

3. Programs and system calls

Utilities such as ls request directory information through operating-system interfaces. A daemon such as sshd is a long-running service process, not a separate hardware layer.

4. Kernel and hardware

The kernel enforces permissions and manages processes, memory, disk drivers and network packets. A network card and disk are hardware controlled through drivers.

Try it on your VM: Example: `ls -l /etc` asks for detailed directory information. Bash launches ls, the kernel provides filesystem metadata, and ls formats it for the terminal. `uname -r` reports the running kernel release.
Practice check: A student says Bash directly controls the hard drive. What is the better explanation?
Explanation: The shell interprets commands. Programs and kernel APIs mediate access to resources; device drivers and the kernel handle hardware.

2. File System Structure

Linux uses one directory hierarchy that begins at /. Instead of drive letters like Windows, devices and filesystems are mounted into this single tree.

/
/home
/root
/etc
/var
/tmp
/usr
/dev
/proc
/mnt

Click a directory

/
The root directory is the starting point of the Linux filesystem.
Navigation examples
pwd        # show current directory
ls -la     # list contents, including hidden files
cd /etc    # move into /etc
cd ~       # go to your home directory
cd ..      # move up one level
Why is /etc especially important to administrators?
Correct answer: It commonly stores system configuration files. Admins often edit files in /etc to configure services, networking, and access settings.

🔎 Deeper explanation: Explore paths, mounts, and directory purpose

Paths

Absolute paths begin with /, for example /etc/ssh. Relative paths depend on your current directory. `~` expands to the user’s home directory in Bash.

Important folders

/etc holds many system-wide settings; /home holds ordinary home directories; /root is the root user’s home; /var/log holds many traditional logs; /proc and /sys expose kernel information; /dev contains device nodes.

Mounts

A disk partition or network filesystem is attached at a directory called a mount point. `lsblk -f`, `findmnt`, and `df -h` reveal different views of storage. Mounting does not automatically make data writable.

Troubleshooting example

A log partition is full. Check `df -h`, then inspect space usage responsibly. Free space in /home does not guarantee space in /var if they are separate filesystems.

Try it on your VM: Try: `pwd`, `cd /etc`, `ls -la`, `cd ~`, `lsblk`, `df -h`. On many modern distributions /bin and /sbin are links into /usr.
Practice check: You are in /home/student and run `cd ../`. Where do you go?
Explanation: `..` means the parent directory. The parent of /home/student is /home.

3. File Operations

Basic file operations let administrators create files, organize folders, move content, copy backups, and remove unnecessary items. These are core daily tasks.

Create

touch file.txt
mkdir project

Copy

cp source.txt copy.txt

Move / Rename

mv old.txt new.txt

Delete File

rm file.txt

Delete Folder

rm -r folder

Danger

rm -rf can be destructive if used carelessly.

Visual workflow
notes.txt  --cp-->  notes-backup.txt
oldname.txt --mv--> newname.txt
oldfolder/ --rm -r--> deleted

Admin mindset

Before running delete commands, always verify where you are with pwd and what exists with ls. Many admin mistakes happen because someone was in the wrong directory.

Which command renames a file without creating an extra copy?
Correct answer: mv old.txt new.txt. The mv command moves or renames a file. cp would create another copy instead.

🔎 Deeper explanation: Safe file handling: create, copy, move, remove

Create

`mkdir -p projects/logs` creates nested directories if needed. `touch notes.txt` creates an empty file or updates its timestamps.

Copy versus move

`cp notes.txt backup.txt` keeps the original and creates a copy; `mv notes.txt archive.txt` renames or moves the original. `cp -r` recursively copies directory contents.

Redirection

`echo "ready" > status.txt` replaces file content. `echo "checked" >> status.txt` appends. Both redirects are processed by the shell and may fail for lack of write permissions.

Delete safely

`rm file.txt` deletes a file; `rm -r folder` recursively deletes. `rm -rf` forces recursive deletion and can destroy data. Verify `pwd` and `ls` before deleting; practise only in a disposable lab folder.

Try it on your VM: Lab: `mkdir -p ~/admin-practice && cd ~/admin-practice && touch notes.txt && cp notes.txt backup.txt && mv backup.txt saved.txt && ls -l`. No real files outside the practice directory are needed.
Practice check: You want to preserve notes.txt and create backup.txt. Which command fits?
Explanation: The copy command preserves the original. The move command would rename or relocate it.

4. View File Content

Admins constantly inspect files: configuration files, logs, reports, and scripts. Different commands are useful depending on what you need to see.

cat

Show an entire short file

cat file.txt

less

Scroll through larger files

less file.txt

head

See the first lines

head file.txt

tail

See the last lines

tail file.txt

tail -f

Watch log entries live

tail -f /var/log/syslog

grep

Search for patterns

grep error file.txt

Log investigation example
tail /var/log/syslog
head /etc/hosts
grep ssh /var/log/auth.log
less /etc/ssh/sshd_config

Use head when you only need the beginning, tail for the latest entries, and grep when you're looking for a specific word or error.

Which command is best for watching new log entries appear in real time?
Correct answer: tail -f /var/log/syslog. The -f option follows a file and shows new entries as they are added.

🔎 Deeper explanation: Read files like an administrator

Choose the right tool

`cat` prints short files; `less` pages through longer output (press q to exit); `head -n 5` gets the first five lines; `tail -n 20` gets the last twenty.

Live monitoring

`tail -f file.log` follows appended text until Ctrl+C. `journalctl -f` can follow systemd journal messages where available.

Search

`grep -i "error" file.log` finds matches without regard to case. `grep -n` includes line numbers, and `grep -R` searches inside directories recursively.

Pipeline

`journalctl -u ssh --no-pager | grep -i failed` pipes log output to a search filter. Pipes connect standard output to the next command’s standard input.

Try it on your VM: Practice safely with your own file: `printf "OK\nERROR DNS\nOK\n" > ~/admin-practice/test.log`, then `cat`, `tail -n 2`, and `grep -n ERROR` on it.
Practice check: Which command will search for error regardless of capitalization?
Explanation: `grep -i` performs a case-insensitive pattern search, so it matches ERROR, Error, and error.

5. Users, Root, and Sudo

Linux uses user accounts to control who is allowed to do what. A normal user should not have unlimited control. The root account is the superuser and can bypass normal restrictions.

Regular User
Daily work, limited permissions
Group Memberships
Shared access to resources
Root
Full administrative control
↓
sudo
Temporary elevation for authorized users
whoami show current user
id show UID, GID, groups
sudo useradd student01 create user
sudo passwd student01 set password

Why sudo is preferred

Using sudo is safer than casually operating as root all the time. It reduces risk, supports better administrative practices, and allows temporary elevated access when needed.

Example
whoami
id
sudo apt update
What is the main purpose of sudo?
Correct answer: To run commands with elevated privileges when authorized. sudo temporarily raises privileges so approved users can perform administrative tasks.

🔎 Deeper explanation: Identity, privilege, and least privilege

User identity

`whoami` reports the effective username. `id` shows user ID, primary group ID and group memberships. Users can have local accounts or accounts supplied by central identity systems.

Groups

Groups let admins grant access to teams rather than setting individual permissions on every file. `groups` shows memberships; `getent group students` checks group entries.

Root

Root typically has UID 0 and broad administrative control. Running routine tasks as root makes mistakes more consequential.

Sudo

`sudo command` runs an authorized command as another user, usually root. Sudo authorization and logging depend on configured policies; it is not a guarantee of perfect auditability.

Try it on your VM: Real server example: an admin uses `sudo systemctl restart ssh` after validating the configuration. `sudo` is not a substitute for knowing what a command will do. On Ubuntu, `adduser` can be a more convenient interactive local account creation tool than `useradd`.
Practice check: Which command shows numeric user and group membership information?
Explanation: `id` reports UID, GID and associated group information; `whoami` only prints the effective username.

Permissions answer three questions: who can access the file, what actions are allowed, and who owns it. Ownership and permissions together determine access.

Visual example

If a script belongs to user student01 but does not have execute permission, the system may refuse to run it directly. Adding execute permission solves that specific problem.

Before
-rw-r--r-- script.sh
Not executable
Command
chmod +x script.sh
After
-rwxr-xr-x script.sh
Executable
What does chmod 755 script.sh do?
Correct answer: Gives the owner rwx and group/others r-x. In octal permissions, 7 = 4+2+1, and 5 = 4+1.

🔎 Deeper explanation: Read, write, execute, ownership, and directories

Read permissions

`-rwxr-x---` starts with file type -, followed by owner rwx, group r-x, and others ---. `ls -l` also shows owner and group names.

Octal math

Read=4, write=2, execute=1. `chmod 750 script.sh` means owner rwx (7), group r-x (5), others no permissions (0). Typical examples include 644 for non-executable documents and 755 for traversable directories.

Directories differ

Directory read lists names; execute allows traversal/search; write plus execute generally permits creating/removing entries, subject to further restrictions. Having write permission on a file is not the same as permission to delete it.

Ownership and security

`chown user:group file` changes both owner and group; `chgrp group file` changes group. ACLs, mount flags and policies such as SELinux/AppArmor can further affect access.

Try it on your VM: Inspect: `ls -ld ~/admin-practice` and `ls -l ~/admin-practice`. Try `chmod 640 ~/admin-practice/test.log` and interpret which users can read it. Avoid `chmod 777` as a blanket fix.
Practice check: A file has mode 640. What can members of its group do under basic Unix permissions?
Explanation: 6=read+write for owner, 4=read for group and 0=no permission for others.

Common service & process commands
systemctl status ssh
sudo systemctl start ssh
sudo systemctl stop ssh
sudo systemctl enable ssh
ps aux
top
kill PID
kill -9 PID

Start vs Enable

Start means run the service now. Enable means configure it to start automatically when the system boots under the appropriate conditions.

start ssh
Runs now
enable ssh
Starts at boot
Which tool is used on many modern Linux systems to manage services?
Correct answer: systemctl. On systemd-based Linux systems, systemctl is commonly used to start, stop, enable, restart, and inspect services.

🔎 Deeper explanation: Daemons, systemd units, and live processes

Service versus process

A process is a running program instance with a PID. A service is a managed function often implemented by one or more processes, commonly supervised by systemd.

State transitions

`systemctl status nginx` inspects status. `sudo systemctl start nginx` starts now; `enable nginx` configures startup at boot; `restart` stops and starts it again.

Process observation

`ps aux` shows a snapshot of processes; `top` updates repeatedly and displays CPU/memory load; `kill PID` sends SIGTERM by default, allowing graceful shutdown. `kill -9` sends SIGKILL and should be a last resort.

Troubleshooting

A service may fail because of bad configuration, occupied ports, missing files, insufficient permission or unavailable storage. Inspect `systemctl status` and `journalctl -u SERVICE`.

Try it on your VM: If your VM has OpenSSH Server installed, investigate `systemctl status ssh`. On Ubuntu/Mint the package may need to be installed first. A service name can differ across distributions.
Practice check: A service works now but fails to start after reboot. Which setting is especially relevant?
Explanation: Starting and enabling are distinct actions. An active service may not be enabled to start automatically.

Troubleshooting logic
ip a          # do I have an address?
ip route      # do I have a gateway?
ping 8.8.8.8 # can I reach the internet by IP?
dig example.com # is DNS working?
ss -tuln      # what services are listening?
If you can ping 8.8.8.8 but cannot open example.com, what is a likely issue?
Correct answer: DNS resolution may be failing. Reaching 8.8.8.8 by IP suggests network connectivity works, while failure to reach a name points toward DNS issues.

🔎 Deeper explanation: Follow the packet: local NIC to DNS and beyond

Addresses

`ip -br addr` summarizes assigned interface addresses and status. A host needs a suitable address and prefix for expected connectivity.

Routes

`ip route` displays the IPv4 routing table. A default route supplies a next hop for destinations that lack more specific routes.

Connectivity tests

`ping -c 4 GATEWAY_IP` tests whether a destination responds to ICMP, but ping can be filtered. Test local gateway, then remote IP, then name resolution.

DNS and listening ports

`dig example.com` or `resolvectl query example.com` checks name resolution where installed. `ss -ltnp` lists listening TCP sockets and their owning processes when permitted.

Try it on your VM: Flow: your browser resolves a name to an IP, chooses a route, and connects to a listening service. A successful ping does NOT prove DNS, HTTPS or SSH will work.
Practice check: The host can reach a public IP, but `dig example.com` times out. What should you investigate?
Explanation: IP connectivity and DNS are separate dependencies. Check the configured resolvers, DNS server availability, and firewall rules.

What is the main reason SSH is preferred over Telnet?
Correct answer: SSH provides encrypted remote access. SSH protects credentials and administrative traffic, making it safer than older plaintext tools such as Telnet.

🔎 Deeper explanation: Read the evidence and manage servers securely

System logs

Many distributions store traditional logs under /var/log. systemd systems may also store logs in a binary journal accessible with journalctl.

Target specific services

`journalctl -u ssh --since today` shows entries associated with the SSH service during the requested period. Permissions determine which logs you can read.

SSH

`ssh admin@192.168.1.10` initiates an encrypted remote connection. Client verifies the server host key; administrators authenticate with approved credentials or SSH keys.

SCP and hardening

`scp file.txt admin@host:/path/` transfers a file over SSH. Prefer unique accounts, SSH keys where appropriate, restricted access and patching. Do not blindly accept unfamiliar SSH host keys.

Try it on your VM: SSH diagnosis: check `ip route`, whether the host can be reached, `systemctl status ssh`, `ss -ltn`, host firewall policy and `journalctl -u ssh`. “Connection refused” and “timed out” imply different starting hypotheses.
Practice check: Why must you check an SSH server host key before trusting a new connection?
Explanation: Server host key verification helps authenticate the remote server and guard against man-in-the-middle attacks.

10. Common Troubleshooting

Effective troubleshooting means checking the most likely causes in a logical order rather than guessing. Match the symptom to the area you should inspect first.

Permission denied
Check ls -l, ownership, chmod, and whether sudo is needed.
Service down
Check systemctl status and journalctl.
SSH fails
Check service status, firewall, network path, credentials, and config.
Disk full
Check df -h.
High CPU
Check top or htop.
Useful command set
ls -l
systemctl status ssh
journalctl -u ssh
df -h
top
ip a
ip route
A server reports “disk full.” Which command is most directly useful first?
Correct answer: df -h. It shows filesystem usage in human-readable units and helps you verify which mounted filesystem is full.

🔎 Deeper explanation: Troubleshooting order: observe → isolate → verify

1. Record symptoms

Which service is unavailable? Does it affect one user, one client or the whole network? Note error text and timing.

2. Check simple dependencies

Inspect address (`ip a`), route (`ip route`), disk space (`df -h`), service status (`systemctl status`), and listening port (`ss -ltn`).

3. Read evidence

Inspect service logs using `journalctl -u NAME`, look for configuration failures, authentication failures, file access errors or port conflicts.

4. Change carefully

Make one controlled change, test it, document what happened, and roll back if needed. Avoid destructive commands and repeated unplanned reboots.

Try it on your VM: Scenario: SSH login works but a website fails. That narrows the problem: investigate the web-service process, its listener, local HTTP response, firewall and logs before blaming the entire network.
Practice check: SSH works, but the web page does not load. What is a sensible next check?
Explanation: A working SSH path shows some network connectivity; checking the web process, listening sockets and logs narrows the failure.

Final Challenge: Think Like a Linux Administrator

Scenario: Users report they cannot access a Linux web server. You can still SSH into the server. Based on what you learned, what should you check?

  1. Verify network information with ip a and ip route.
  2. Check whether the web service is running with systemctl status nginx or the appropriate service name.
  3. Review relevant logs with journalctl -u nginx or logs under /var/log.
  4. Check for listening sockets with ss -tuln.
  5. Check disk space with df -h in case the service cannot write logs or temporary files.
  6. Inspect permissions or ownership if the service cannot access its files.
What is the best first mindset in Linux troubleshooting?
Correct answer: Check likely causes in a logical order and gather evidence. Strong admins troubleshoot methodically instead of guessing.
