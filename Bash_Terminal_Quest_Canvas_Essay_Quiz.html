Answer 1. Meet the Terminal (5 points)

pwd prints the absolute path to the current working directory, such as /home/student. It helps confirm the location before creating, changing, or deleting files.

Answer 2. See What Is Here (4 points)

ls lists the visible file and directory names in the current working directory (or a supplied path). It does not normally include hidden dotfiles.

Answer 3. Hidden Intel (4 points)

Names beginning with . are hidden from standard ls output. ls -a includes them, including configuration files such as .bashrc; reviewing these can help diagnose user-level settings.

Answer 4. Navigate the Filesystem (4 points)

cd projects moves from /home/student to /home/student/projects; cd /home/student/projects uses the full absolute path. Relative paths are interpreted from the current location, while absolute paths begin at /.

Answer 5. Verify Your Location (5 points)

cd ~/projects enters the projects directory from anywhere if the home directory is /home/student; pwd confirms /home/student/projects.

Answer 6. Create a Work Folder (4 points)

Use cd ~/projects then mkdir lab, or mkdir ~/projects/lab. mkdir creates a directory if its parent exists; mkdir -p can also create missing parent directories and does not error if the destination already exists.

Answer 7. Enter Your Workspace (4 points)

Use cd ~/projects/lab then pwd; the result is /home/student/projects/lab. Relative file operations use the current working directory, so a wrong location can affect the wrong files.

Answer 8. Create a Log File (4 points)

Use touch network.log. If it does not exist it creates an empty file; if it exists, touch updates its timestamps and does not normally erase its contents.

Answer 9. Write a Status Update (5 points)

echo &quot;Network ready&quot; &gt; network.log writes the text and a newline, creating or overwriting the file. &gt; replaces existing content; &gt;&gt; appends to the end.

Answer 10. Read Your Log (4 points)

Run cat network.log; the terminal should display Network ready. cat prints file contents without modifying them.

Answer 11. Create a Backup (4 points)

cp network.log backup.log duplicates the file. The original stays in place. A backup preserves a known version before later changes.

Answer 12. Rename the Backup (4 points)

mv backup.log network-backup.log renames the file so the old pathname is gone. cp makes another file and keeps the source; mv moves or renames the existing file.

Answer 13. Search the Evidence (4 points)

grep DNS ~/projects/incidents.txt prints matching lines. grep -i DNS ~/projects/incidents.txt searches case-insensitively.

Answer 14. Read a File’s Beginning (4 points)

head ~/projects/incidents.txt displays the beginning (10 lines by default on common implementations); head -n 5 ~/projects/incidents.txt requests five lines. It is useful for checking headers or first entries.

Answer 15. Read a File’s Ending (4 points)

tail ~/projects/incidents.txt shows the final lines (typically 10 by default). tail -f ~/projects/incidents.txt continues displaying newly appended lines, useful for monitoring live logs.

Answer 16. Count the Lines (4 points)

wc -l ~/projects/incidents.txt counts newline characters and is conventionally used as a line-count command. -l selects line counting.

Answer 17. Check Your Identity (4 points)

whoami prints the effective current username. Checking it helps ensure you are working under the expected account and privileges.

Answer 18. Learn About the Kernel (4 points)

uname -s prints the kernel name (commonly Linux). uname -a displays a broader set of system/kernel details, such as name, release, version, and machine information.

Answer 19. Understand Permissions (4 points)

ls -l ~/projects shows long-format details such as permission bits, link count, owner, group, size, modification time, and filename. The permission string shows read/write/execute access for user, group, and others.

Answer 20. Make a Script Executable (5 points)

chmod +x ~/projects/check.sh adds execute permission (subject to ownership and system policy). Execute permission controls whether a file can be launched as a program; inappropriate access may create a security risk.

Answer 21. Check the Network Address (4 points)

ip addr (or ip a) shows network interfaces and assigned addresses. Inspect interface state (UP/DOWN), IPv4/IPv6 address, prefix length, and whether the expected interface has an address.

Answer 22. Test Connectivity (4 points)

ping -c 4 192.168.10.1 sends four ICMP echo requests. Replies suggest network-layer reachability and provide timing information; they do not prove that a particular application or service is available.

Answer 23. Inspect the Route (4 points)

ip route lists routes, including a line starting with default via when configured. Without an appropriate route to a remote subnet, the machine may not know where to send packets beyond directly connected networks.

Answer 24. Final: Build a Handoff Note (4 points)

cd ~/projects/lab then echo &quot;Shift complete&quot; &gt; handoff.txt then cat handoff.txt. The final command checks that the expected content was written to the intended file in the intended location.
